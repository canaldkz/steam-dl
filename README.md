# steam-dl

Автоматизация активации, загрузки и настройки игр под Linux-портативки
(Bazzite / SteamOS) с **SteamTools + PortProton** и последующим запуском через
**нативный Steam в Game Mode**.

Реализует линейный конечный автомат из пяти этапов: инъекция манифестов →
запуск изолированной среды → поллинг загрузки → перемещение и обход DRM
(Goldberg) → интеграция в нативный Steam. Каждый этап проверяет свою
пост-условие (assertion) перед переходом к следующему.

Ядро не имеет сторонних зависимостей — кодеки VDF (текстовый и бинарный) и
клиент списка приложений Steam написаны на стандартной библиотеке, поэтому
инструмент работает на «голом» образе портативки. `PyYAML` нужен только если
вы описываете игру в YAML.

## Установка

```bash
pip install -e .           # ядро, без зависимостей
pip install -e .[yaml]     # + поддержка YAML-спеков
```

Появится команда `steam-dl`.

## Быстрый старт

```bash
# что видит инструмент в системе
steam-dl env

# найти appid по названию
steam-dl search "Half-Life 2"

# «прогон» без изменений — покажет все действия
steam-dl install 220 --dry-run -v

# полный цикл по спеку с депотами и ключами
steam-dl install --spec examples/game.example.yaml \
    --goldberg-dir ~/Goldberg --prefix STEAM
```

Формат спека — в `examples/game.example.yaml`.

## Архитектура

```
CLI ──> pipeline (state machine)
           │
           ├─ Backend (этапы 1–3): PortProton/SteamTools  ИЛИ  DepotDownloader
           │      └─ возвращает каталог установленной игры
           ├─ Этап 4: relocate → ~/Games + Goldberg-патч + steam_appid.txt
           └─ Этап 5: shortcuts.vdf + config.vdf (CompatToolMapping) → Game Mode
```

- `steam_dl/vdf/` — независимые кодеки VDF: `text` (config.vdf, .acf),
  `binary` (shortcuts.vdf). Байт-совместимы с эталонной библиотекой `vdf`.
- `steam_dl/steam/` — вычисление appid ярлыка, разбор `.acf` (StateFlags),
  запись shortcuts/config, поиск игр по имени.
- `steam_dl/backends/` — сменные бэкенды загрузки.
- `steam_dl/stages/` — этапы 1, 3, 4, 5 как отдельные проверяемые функции.

## Разбор исходного алгоритма: найденные проблемы и решения

Присланный алгоритм в целом верный, но при реализации выявились несколько
реальных дефектов. Что исправлено:

1. **Порядок правки файлов нативного Steam (критично).** В исходном плане
   `shortcuts.vdf` и `config.vdf` редактируются в этапе 5, а Steam
   перезапускается только в самом конце. Но Steam держит эти файлы в памяти и
   **перезаписывает их при выходе**, молча теряя любые правки, сделанные пока
   он запущен. Здесь Steam сначала останавливается (`SIGTERM`), затем правятся
   файлы, затем запускается снова (`integrate.py`).

2. **StateFlags — это битовое поле, а не перечисление.** Значения 1026/1042/4
   из гайдов — просто частые *комбинации* битов. Жёсткая проверка на эти числа
   ломается на валидации/преаллокации/докачке. `acf.py` декодирует отдельные
   биты и дополнительно сверяет `BytesDownloaded == BytesToDownload`, чтобы не
   принять «ещё коммитится» за «установлено».

3. **Ключ CompatToolMapping должен совпадать с appid ярлыка.** В плане appid
   считается как «CRC32 от Exe+AppName», но не оговорено, что *та же* величина
   (32-битная, со старшим битом) должна быть и в `shortcuts.vdf`, и ключом в
   `config.vdf` — иначе Proton не применится. Мы вычисляем appid один раз и
   пишем его явно в оба места (проверено сквозным тестом).

4. **CRC берётся от Exe *с кавычками*.** Steam хэширует строку Exe ровно так,
   как она лежит в `shortcuts.vdf` — а там путь в кавычках. Считать CRC от пути
   без кавычек → неверный appid. `shortcuts.py` нормализует кавычки перед
   вычислением.

5. **Идемпотентность.** Повторный запуск не должен плодить дубликаты ярлыков.
   `add_shortcut` дедуплицирует по (Exe, AppName), а Goldberg делает резервную
   копию оригинальной DLL (`.orig`) и не перетирает её повторно.

6. **Хрупкие внешние вызовы.** `flatpak run ... -p <PREFIX>` и
   `wineserver -k` вынесены в конфиг и обёрнуты обработкой ошибок/таймаутами;
   бинарные имена (`flatpak`, `steam`, `DepotDownloader`) настраиваемы.

### Более крупное предложение по архитектуре: бэкенд DepotDownloader

Главная идея. Если у вас **уже есть ключи депотов** (а в алгоритме они
фигурируют), то весь стек PortProton + Wine + SteamTools для *загрузки* не
нужен. [DepotDownloader](https://github.com/SteamRE/DepotDownloader) —
кроссплатформенный .NET-инструмент — качает депоты прямо с CDN Steam по
appid/depot/manifest/key. Это убирает этапы 2 и 3 целиком (нет запуска
Windows-Steam, нет поллинга `.acf`, нет `wineserver -k`), снижает число точек
отказа и качает сразу в `~/Games`, так что этап 4a (перемещение) становится
пустой операцией. Этапы Goldberg и интеграции в Steam — общие.

Выбор бэкенда — флагом `--backend`:

```bash
# без Wine, если известны ключи
steam-dl install --spec game.yaml --backend depotdownloader
```

Бэкенд PortProton/SteamTools остаётся как полная реализация исходного
сценария (например, когда `.manifest` проще получить через SteamTools).

### Замечания и ограничения

- **Патчинг steam_api DLL** работает для игр на легковесной защите Steam.
  Игры с CEG/Denuvo/иным DRM он не обойдёт — это ожидаемо.
- **Возврат в Game Mode.** На Bazzite/SteamOS игровой режим — это отдельная
  сессия (`gamescope-session`), а не флаг `steam -gamepadui`. Инструмент
  корректно перезапускает *клиент* Steam, чтобы новый ярлык подхватился, но
  переключение сессии в Game Mode оставлено системе (см. `--restart-steam`,
  по умолчанию выключено, чтобы не мешать текущей сессии).
- **`.manifest`-файлы** не синтезируются из ключей — это бинарные данные от
  Steam. Их можно передать каталогом через `--manifest-source`; иначе
  инструмент полагается на манифесты, уже присутствующие в префиксе.
- Аргумент `flatpak run ... -p <PREFIX_NAME>` соответствует запуску
  PortProton; если ваша сборка вызывает префикс иначе — переопределите команду
  в конфиге.

## Конфигурация

Значения по умолчанию рассчитаны на Bazzite и лежат в `steam_dl/config.py`.
Любое можно переопределить флагом CLI или файлом (`-c config.yaml`):

```yaml
backend: portproton          # или depotdownloader
prefix_name: STEAM
goldberg_dir: ~/Goldberg
games_dir: ~/Games
proton_tool: GE-Proton
restart_steam: false
```
